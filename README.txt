1. プロジェクトの基本情報
    ==================================================

■ プロジェクト名
One for All COSMOS

■ GitHubリポジトリ
https://github.com/gtakeru54-stack/One-for-All

■ 公開URL
https://gtakeru54-stack.github.io/One-for-All/

■ 開発環境
・iPhone
・GitHubアプリ
・GitHub Pages
・HTML / CSS / JavaScript
・PWA（ホーム画面に追加してアプリのように使用）
・データ保存は基本的にlocalStorage

■ デザイン方針
・宇宙、星、ロケットをテーマにする
・背景は濃い紺色を中心にする
・基本背景色は #070b19
・現代的で使いやすいデザイン
・スマートフォンで使いやすい配置
・学習時間や目標の進捗を視覚的に表示する
・画面下部のメニューから各機能へ移動できるようにする

■ 開発の最終目標
学習記録、タイマー、カレンダー、タスク、統計、目標マップ、ロケット、ゲーム内経済のような経済機能、カウントダウン、通知、設定を一つにまとめた学習管理アプリを作る。

■ 最重要ルール
このアプリは、勉強した内容を他人に共有するためのアプリではない。
自分が何をどれくらい勉強したかを記録し、自分の成長を確認するためのアプリにする。

2. 開発時に絶対に守ること

1. コードはダウンロードファイルではなく、チャット内のテキストで渡す。
2. コードを修正するときは、原則としてファイル全体を提示する。
    変更部分だけの断片的なコードは、ユーザーが明確に希望した場合を除いて使わない。
3. 必ずファイル名と保存場所を記載する。
4. 変更するファイルと、変更しないファイルを明確にする。
5. 一度に大量のファイルを変更せず、原則として一つずつ進める。
6. 小さな修正のために無関係なファイルまで変更しない。
7. 既存の機能、保存データ、デザインをできるだけ壊さない。
8. 同じ機能を複数のファイルで二重に初期化しない。
9. コードを書いたことと、Minecraftやブラウザなどで実際に動作確認したことを区別する。
10. 実際にテストしていない機能を「実装完了」「動作確認済み」と断言しない。
11. 新しいコードを渡した後は、どこに貼り付けるか、何を置き換えるか、次に何を確認するかを説明する。
12. ユーザーが「次」と言った場合は、現在の作業順序を引き継いで次のファイルや工程へ進む。
13. ファイルが存在するか、保存されているか、テスト済みかを勝手に決めつけない。
14. 既存データを消去する処理は、必要性を確認せずに追加しない。

3. 現在の開発方式

現在は、大きな app.js にすべての機能を詰め込む方式から、機能ごとにJavaScriptファイルを分割する方式へ移行している。

基本方針は次のとおり。

・index.html
画面のHTML構造を管理する。

・css/style.css
見た目、配置、色、スマートフォン向け表示を管理する。

・js/ui.js
画面切り替え、共通ダイアログ、メッセージ表示などを管理する。

・js/navigation.js
画面切り替えとナビゲーションを管理する。

・js/storage.js
データの保存、読み込み、保存キーなどを管理する。

・js/study.js
学習科目、学習項目、学習記録を管理する。

・その他のjsファイル
カレンダー、統計、目標、ロケット、経済など、各機能を個別に管理する。

重要：
index.htmlから読み込むJavaScriptの入口は js/ui.js とする。

app.jsは古い一体型コードとして残っているが、現在のindex.htmlからは読み込まない。
動作確認と移行が完了するまでは、app.jsを削除しない。
